# B-21 UI詳細仕様

Status: Draft / partially accepted
Decision ID: B-21

## 1. Home画面の基本レイアウト

ホームは「今日、マネージャーが見るべき判断材料」を最短で把握できる構成にする。

### 上段: 4枚のサマリーカード

PCでは横並び4列を基本とする。

現時点のイメージ:

1. 今日の異常
2. 今日の要確認
3. 今日の委譲候補
4. 今日の褒める候補

重要:
- 上記4項目の名称・最終カテゴリは未確定。
- ただし「今日の重要な判断材料を、少数のカードとして横並びで即時把握する」というレイアウト原則は採用する。
- 各カードは件数だけではなく、最重要1〜3件へ遷移できる設計を想定する。
- KPI達成率だけをトップに置くダッシュボードにはしない。

### 下段: 3つの情報ブロック

PCでは横並び3列を基本とする。

現時点のイメージ:

1. 確認事項リスト
2. 今日のスケジュール
3. チーム状態

重要:
- 項目名・表示詳細は未確定。
- 「サマリーカードの次に、今日の行動・時間・チーム状況を3ブロックで確認する」という情報階層は採用する。

## 2. 情報階層

Homeは次の順で設計する。

```text
今日のシグナル
↓
今日確認・対応すべき具体項目
↓
今日の時間制約 / スケジュール
↓
チーム全体の状態
```

COMESは管理帳票ではなくManagement OSであるため、網羅性よりも「今日の判断に必要な情報」を優先する。

## 3. PC / Mobile

PC:
- 上段カードは4列
- 下段ブロックは3列
- 一画面で全体像を把握できることを優先

Mobile:
- PCを単純縮小しない
- 上段カードは重要度順に縦配置、または横スワイプ可能なカード群を候補とする
- 下段ブロックは縦順に並べる
- 最終的なMobile順序は別途確定する

## 4. 未確定事項

以下は追加確認後に確定する。

- 上段4カードの正式カテゴリ
- 各カード内に表示する情報量
- カードクリック時の遷移先
- 確認事項リストの生成元
- 今日のスケジュールのデータソース
- チーム状態の定義と表示項目
- Mobileでのカード表現
- 空状態 / エラー状態

## 5. Acceptance

現時点で確定したこと:

- Home最上段は少数の「今日のシグナル」カード群
- KPI中心の従来型ダッシュボードを主役にしない
- その下に「確認事項 / スケジュール / チーム状態」に相当する3情報ブロックを置く
- PCとMobileは同一データでも情報配置を最適化する
