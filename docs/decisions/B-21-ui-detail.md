# B-21 UI詳細仕様

Status: Draft / partially accepted
Decision ID: B-21

## 1. Home画面の基本レイアウト

ホームは「今日、マネージャーが見るべき判断材料」を最短で把握できる構成にする。

### 上段: 4枚のサマリーカード

PCでは横並び4列を基本とする。

現時点のイメージ:

1. 今日の異常
2. 今日の要確認
3. 今日の委譲候補
4. 今日の褒める候補

重要:
- 上記4項目の名称・最終カテゴリは未確定。
- ただし「今日の重要な判断材料を、少数のカードとして横並びで即時把握する」というレイアウト原則は採用する。
- 各カードは件数だけではなく、その日の重要シグナルへの入口として機能する。
- KPI達成率だけをトップに置くダッシュボードにはしない。

### 下段: 3つの情報ブロック

PCでは横並び3列を基本とする。

現時点のイメージ:

1. 確認事項リスト
2. 今日のスケジュール
3. チーム状態

重要:
- 項目名・表示詳細は未確定。
- 「サマリーカードの次に、今日の行動・時間・チーム状況を3ブロックで確認する」という情報階層は採用する。

## 2. HomeのInteraction Pattern

Homeでは画面遷移を最小化し、判断と一次処理を同じ文脈で完結させる。

### 2.1 サマリーカード押下

上段カードを押下した場合、別ページへ即遷移させない。

PCでは中央に大きめのModal Dialogを表示する。

採用する見え方:
- 画面中央に幅広のモーダルを表示
- 元のHome画面は背面に残す
- 背景には半透明の暗いoverlayをかけ、視覚的に弱める
- モーダルを現在の判断対象として明確にフォーカスする
- 右側Drawerを標準パターンにはしない

目的:
- 現在地を失わない
- 画面遷移を減らす
- 「見る → 判断する → 軽い処理をする」を短い操作で完結させる

### 2.2 Modal内で完結させる操作

Modal内では、対象一覧の確認と軽量な一次操作までを許可する。

例:
- 詳細を見る
- 確認済みにする
- 委譲候補として採用 / 保留
- 褒めた / 後で対応

ただし、操作名は対象カテゴリごとに最終確定する。

### 2.3 詳細画面へ遷移する境界

次のような情報量の多い対象のみ専用画面へ遷移する。

- 案件詳細
- 人物詳細
- KPI詳細推移
- 1on1履歴
- Bottleneck詳細
- Decision Pack全体

原則:

```text
Home Card
  ↓
Centered Modal
  ↓
一覧確認 + 一次操作
  ↓ 必要な場合のみ
Detail Page
```

Homeは「判断・確認のコックピット」とし、深い分析画面とは分離する。

## 3. 情報階層

Homeは次の順で設計する。

```text
今日のシグナル
↓
今日確認・対応すべき具体項目
↓
今日の時間制約 / スケジュール
↓
チーム全体の状態
```

COMESは管理帳票ではなくManagement OSであるため、網羅性よりも「今日の判断に必要な情報」を優先する。

## 4. PC / Mobile

PC:
- 上段カードは4列
- 下段ブロックは3列
- 一画面で全体像を把握できることを優先
- カード詳細は中央Modalを基本とする

Mobile:
- PCを単純縮小しない
- 上段カードは重要度順に縦配置、または横スワイプ可能なカード群を候補とする
- 下段ブロックは縦順に並べる
- 詳細表示は画面幅を大きく使うModal / Sheetを候補とし、PC Modalの単純縮小はしない
- 最終的なMobile順序・表現は別途確定する

## 6. Acceptance

現時点で確定したこと:

- Home最上段は少数の「今日のシグナル」カード群
- KPI中心の従来型ダッシュボードを主役にしない
- その下に「確認事項 / スケジュール / チーム状態」に相当する3情報ブロックを置く
- 上段カードの詳細はPCでは中央Modalで表示する
- Modal表示時は元画面をoverlayで薄くし、現在地を保持する
- Modal内で一覧確認と軽量な一次操作を完結させる
- 深い分析のみ詳細ページへ遷移する
- PCとMobileは同一データでも情報配置を最適化する
