# B-21 UI詳細仕様

Status: Draft / partially accepted
Decision ID: B-21

## 1. Home画面の基本レイアウト

ホームは「今日、マネージャーが見るべき判断材料」を最短で把握できる構成にする。

### 上段: 4枚のサマリーカード

PCでは横並び4列を基本とする。

現時点のイメージ:

1. 今日の異常
2. 今日の要確認
3. 今日の委譲候補
4. 今日の褒める候補

重要:
- 上記4項目の名称・最終カテゴリは未確定。
- ただし「今日の重要な判断材料を、少数のカードとして横並びで即時把握する」というレイアウト原則は採用する。
- 各カードは件数だけではなく、その日の重要シグナルへの入口として機能する。
- KPI達成率だけをトップに置くダッシュボードにはしない。

### 下段: 3つの情報ブロック

PCでは横並び3列を基本とする。

現時点のイメージ:

1. 確認事項リスト
2. 今日のスケジュール
3. チーム状態

重要:
- 項目名・表示詳細は未確定。
- 「サマリーカードの次に、今日の行動・時間・チーム状況を3ブロックで確認する」という情報階層は採用する。

## 2. HomeのInteraction Pattern

Homeでは画面遷移を最小化し、判断と一次処理を同じ文脈で完結させる。

### 2.1 サマリーカード押下

上段カードを押下した場合、別ページへ即遷移させない。

PCでは中央に大きめのModal Dialogを表示する。

採用する見え方:
- 画面中央に幅広のモーダルを表示
- 元のHome画面は背面に残す
- 背景には半透明の暗いoverlayをかけ、視覚的に弱める
- モーダルを現在の判断対象として明確にフォーカスする
- 右側Drawerを標準パターンにはしない

目的:
- 現在地を失わない
- 画面遷移を減らす
- 「見る → 判断する → 軽い処理をする」を短い操作で完結させる

### 2.2 Modal内で完結させる操作

Modal内では、対象一覧の確認と軽量な一次操作までを許可する。

例:
- 詳細を見る
- 確認済みにする
- 委譲候補として採用 / 保留
- 褒めた / 後で対応

ただし、操作名は対象カテゴリごとに最終確定する。

### 2.3 詳細画面へ遷移する境界

次のような情報量の多い対象のみ専用画面へ遷移する。

- 案件詳細
- 人物詳細
- KPI詳細推移
- 1on1履歴
- Bottleneck詳細
- Decision Pack全体

原則:

```text
Home Card
  ↓
Centered Modal
  ↓
一覧確認 + 一次操作
  ↓ 必要な場合のみ
Detail Page
```

Homeは「判断・確認のコックピット」とし、深い分析画面とは分離する。

## 3. タスク画面

タスク画面は「今日やること」を最優先にし、時間軸で整理する。

### 3.1 基本3分類

タスクは次の3グループを基本とする。

1. 今日やること
2. 1週間以内にやること
3. 急ぎじゃない

この3分類をタスク画面の主たる情報構造とする。

優先度は明確に次の順とする。

```text
今日やること
↓
1週間以内にやること
↓
急ぎじゃない
```

「今日やること」はPCでも視覚的に最優先領域として扱う。

### 3.2 採用するPCレイアウト

PCでは3つの時間軸を横並びのボードとして表示する。

左から:

1. 今日やること
2. 1週間以内にやること
3. 急ぎじゃない

各列にはタスクカードを縦に並べる。

タスクカードの基本情報:
- タスク名
- 簡潔な説明
- 担当者 / 関係者
- 期限
- 必要に応じたコメント・関連情報
- 補助シグナル

「今日やること」は背景・見出しなどで他列よりも視覚的に強くし、最初に目へ入る構成とする。

### 3.3 マネジメント判断は補助シグナルとして付与する

各タスクには、必要に応じてCOMESが管理上の候補シグナルを付与する。

例:
- 期限切れ
- 停滞
- 委譲候補
- 仕組み化候補
- 要レビュー
- レビューだけでよい候補
- 高リスク / 要確認

これらはタスクの所属グループではなく、タスクに付く補助ラベル / シグナルとして扱う。

「停滞」は「本来進むはずのタスクが一定期間更新されていない / 待ち理由により止まっている」状態を示す。

「通常」というラベルは持たない。特別なシグナルがないタスクにはラベルを付けない。

### 3.4 仕組み化候補

仕組み化候補は、人間が手動で分類するだけではなく、ルールベースで候補抽出できるようにする。

候補条件の例:
- 同種タスクが一定回数以上繰り返されている
- 同じ人が同じ処理を反復している
- 毎週 / 毎月の定型作業である
- 期限切れや持ち越しが繰り返される
- 差し戻しが複数回発生している
- 手順化すれば他者へ移管できそうである

重要:
- COMESは「仕組み化すべき」と断定しない。
- 「仕組み化候補」として根拠付きで提示する。
- 頻度・履歴が不足している場合は推測しない。

### 3.5 委譲判断

「任せる」はタスク画面の固定レーンではなく、各タスクを見たうえで判断する。

B-07の委譲評価軸を利用し、必要に応じて:
- 委譲候補
- レビュー付き委譲候補
- マネージャー保持候補

として表示する。

タスク画面では、実行優先順位とマネジメント判断を混同しない。

原則:

```text
When = 今日 / 1週間以内 / 急ぎじゃない
How = 自分でやる / 任せる / レビュー / 仕組み化
```

「When」を主構造、「How」を判断シグナルとする。

## 4. チーム画面

チーム画面は人事評価画面ではなく、マネージャーがチーム内の偏り・変化・要フォロー対象を横比較するための画面とする。

### 4.1 PCの基本表示

PCでは、メンバーをカード一覧ではなく「横長の行」で一覧表示する方向を採用する。

目的:
- 複数メンバーを同時に比較しやすくする
- KPI、負荷、変化、要フォローなどの偏りを一目で把握する
- 人物プロフィールを見る画面ではなく、管理判断の入口として機能させる

基本イメージ:

```text
メンバー | 役割 | KPI | 直近の変化 | 仕事量 | 委譲候補 | 要フォロー | 褒める候補
--------------------------------------------------------------------------
田中     | 営業 | ... | ...        | ...    | ...      | ...        | ...
山田     | 営業 | ... | ...        | ...    | ...      | ...        | ...
鈴木     | CS   | ... | ...        | ...    | ...      | ...        | ...
```

各行はクリック可能とし、必要に応じて人物詳細へ遷移する。

重要:
- 「評価点」「モチベーション点」などの人物スコアは表示しない
- 数字だけで人を良し悪し判断するUIにしない
- 事実・変化・候補シグナルを中心にする
- 要フォローや褒める候補には根拠が追えること

### 4.2 人物詳細との役割分担

チーム一覧は比較と入口に特化する。

人物詳細では必要に応じて:
- 現在の仕事
- KPI履歴
- 最近の変化
- 要フォロー候補
- 褒める候補
- Manager Observation
- 1on1要約
- 委譲候補

を深掘りする。

チーム一覧に全履歴を詰め込まない。

## 5. 情報階層

Homeは次の順で設計する。

```text
今日のシグナル
↓
今日確認・対応すべき具体項目
↓
今日の時間制約 / スケジュール
↓
チーム全体の状態
```

COMESは管理帳票ではなくManagement OSであるため、網羅性よりも「今日の判断に必要な情報」を優先する。

## 6. PC / Mobile

PC:
- Home上段カードは4列
- Home下段ブロックは3列
- 一画面で全体像を把握できることを優先
- カード詳細は中央Modalを基本とする
- タスク画面は3つの時間軸グループを横並びで同時に俯瞰する
- 左端の「今日やること」を最優先表示する
- チーム画面は横長行による比較一覧を基本とする

Mobile:
- PCを単純縮小しない
- Home上段カードは重要度順に縦配置、または横スワイプ可能なカード群を候補とする
- Home下段ブロックは縦順に並べる
- 詳細表示は画面幅を大きく使うModal / Sheetを候補とし、PC Modalの単純縮小はしない
- タスクは「今日 → 1週間以内 → 急ぎじゃない」の縦順を基本候補とする
- チーム一覧はPCの横長行をそのまま縮小せず、重要情報を縦カード化する方向を候補とする
- 最終的なMobile順序・表現は別途確定する

## 8. Acceptance

現時点で確定したこと:

- Home最上段は少数の「今日のシグナル」カード群
- KPI中心の従来型ダッシュボードを主役にしない
- その下に「確認事項 / スケジュール / チーム状態」に相当する3情報ブロックを置く
- Home上段カードの詳細はPCでは中央Modalで表示する
- Modal表示時は元画面をoverlayで薄くし、現在地を保持する
- Modal内で一覧確認と軽量な一次操作を完結させる
- 深い分析のみ詳細ページへ遷移する
- タスク画面の主分類は「今日 / 1週間以内 / 急ぎじゃない」
- 「今日やること」を常に最優先表示する
- PCタスク画面は3列ボードを採用する
- 委譲・レビュー・仕組み化・期限切れ・停滞は補助シグナルとして扱う
- 「通常」という補助ラベルは設けない
- 仕組み化候補は反復・期限切れ・差し戻し等の履歴から根拠付きで候補抽出する
- PCチーム画面は横長行でメンバー比較できる一覧を基本とする
- チーム画面は人事評価ではなく管理判断材料の比較画面とする
- PCとMobileは同一データでも情報配置を最適化する
