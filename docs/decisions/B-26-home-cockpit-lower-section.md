# B-26 Home下段コクピット仕様

Status: Accepted v0.1
Decision ID: B-26

## 1. 目的

Home下段は、上段4カードの内容を再掲する場所ではなく、マネージャーが当日の判断を行うための「前提条件・現在地」を確認するコクピットとして扱う。

上段4カード:
- 自分が動く
- 手放す
- 褒める
- 詰まりを取る

下段はそれらと役割を分離し、時間・数字・組織の現在地を示す。

## 2. 下段3ブロック

PCでは横並び3列を基本とする。

1. 今日のスケジュール
2. 今月の進捗 + AIコメント
3. チーム状態

役割:
- 今日のスケジュール = 時間の事実
- 今月の進捗 + AIコメント = 数字の現在地とAIによる解釈
- チーム状態 = 組織の事実

## 3. 今日のスケジュール

会社ごとに予定管理方法が異なるため、特定サービスをCOMES Coreの前提にしない。

原則:
- 手入力を最低保証とする。
- 会社ごとに任意の連携元を追加できる設計とする。
- Google Calendar、Outlook、CRMの商談予定、シフト管理、独自API等はAdapterとして追加可能にする。
- 取得元が異なっても、COMES内では共通のSchedule Eventに正規化して表示する。

Schedule Eventの最小候補:
- start_at
- end_at
- title
- event_type
- related_person_ids / related_person_names
- source_type
- source_id
- is_fixed

MVPでは連携先を増やしすぎず、手入力 + 必要最小限の1連携を基本とする。

## 4. 今月の進捗 + AIコメント

### 4.1 対象

プレイングマネージャー向けのため、次の両方を扱う。
- 自分のKPI
- チームのKPI

### 4.2 KPI定義

KPIそのものは会社固有とし、COMES Coreに固定しない。

COMESはKPIの共通定義枠を持つ。

最小候補:
- kpi_id
- name
- scope: self / team
- target_value
- actual_value
- period
- unit
- source_type
- calculation_rule
- description

会社ごとにKPI名・意味・計算方法・取得元を設定可能にする。

MVPでは汎用KPIビルダーを作り込まず、数個のKPIを設定できる程度で成立させる。

### 4.3 AIコメント

AIコメントは別処理で生成せず、日次AI分析の中で同時に生成する。

フロー:

```text
当月KPI実績
→ Decision Pack
→ 日次AI分析
→ 翌日のHomeに最新コメント表示
```

コメントは「数字の読み上げ」ではなく、マネージャーへの示唆を短く返す。

例:
- 目標との差
- 自分とチームのバランス
- 前週・前月からの変化
- 今後優先すべきマネジメント観点

AIはKPIの意味を推測せず、COMESから渡された定義・目標・実績・推移・対象を根拠に解釈する。

## 5. チーム状態

チーム状態はAIによる人物評価画面にしない。

表示は事実ベースとする。

主な候補:
- メンバーごとのタスク数
- 負荷偏り
- 期限超過件数
- 停滞件数
- 直近1on1実施日
- 委譲候補数
- 要フォロー候補数
- 褒める候補数
- KPI進捗のばらつき
- 最近の観測された変化

原則:
- モチベーション推定を行わない。
- 人物スコアを表示しない。
- AIコメントは隣の「今月の進捗 + AIコメント」に寄せ、チーム状態自体は事実表示を優先する。

## 6. 責務分界

- 会社固有: KPI定義、予定の取得元、外部システム
- COMES: 共通フォーマットへの正規化、事実保持、表示、Decision Pack化
- AI: 定義済み事実をもとに意味づけ・優先順位・短い示唆を生成

COMES Coreには特定会社・特定業態のKPI名や予定システムをハードコードしない。

## 7. Home全体の役割分担

```text
上段 = 今日どう動くか
  自分が動く / 手放す / 褒める / 詰まりを取る

下段 = 判断の前提となる現在地
  今日のスケジュール / 今月の進捗 + AIコメント / チーム状態
```

これによりHomeを「管理帳票」ではなく、プレイングマネージャーの判断コクピットとして扱う。
