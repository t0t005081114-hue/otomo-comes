# B-29 Home状態表現・警告・Mobile方針

Status: Accepted v0.2
Decision ID: B-29

## 1. 空状態

Home上の対象が当日0件の場合、単純な空表示にはしない。

原則:
- 当日分が0件なら、翌日以降の予定・候補・関連情報を表示対象にする。
- スケジュールについては、当日0件の場合に限り、翌日以降で最も近い予定を1件だけ表示する。
- 未来情報は当日情報と混同しないよう、日付やラベルで明示する。
- 「何もない」ではなく、次に見るべき未来の情報へ自然に接続する。

目的:
- コクピットを空白にしない
- 次の判断につながる情報を維持する
- 空状態そのものを不安・警告として見せない

## 2. 警告表現

COMES Homeでは警告を強調しすぎない。

原則:
- 強い赤・大きな警告帯・点滅・過度なバッジ増加などは避ける。
- 色や視覚強調を増やしすぎない。
- マネージャーに追加の心理負荷を与えない。
- 「異常を煽るUI」ではなく、落ち着いて判断できるクリエイティブを優先する。
- 重大な事実も、文脈・優先順位・次の一手が分かる形で静かに提示する。

COMESの人格として、プレッシャーをかける管理画面ではなく、判断を軽くするコクピットを目指す。

## 3. 色・強調ルール

色は情報分類や可読性補助に限定し、感情的な強調には使わない。

原則:
- カードごとに派手な固有色を持たせない。
- 高優先度だからといって全面を強色にしない。
- 必要な場合はアイコン、短いラベル、細いアクセント、文字ウェイト程度で差を出す。
- 重要度はレイアウト順・文言・情報密度で伝える。

## 4. データ鮮度

データの最終更新時刻は表示するが、主役にしない。

原則:
- Homeの端・補助領域に小さく表示する。
- 例: `最終更新 10:42`
- 通常時は低コントラストでよい。
- データ取得失敗など、意味のある異常がある場合だけ文言で明示する。

## 5. Mobile

MobileはPCの縮小版にしない。

最優先:
- スクロール時の視認性
- 1画面内の認知負荷軽減
- 上から順に自然に判断できる構成

基本方針:
- 上段4カードは縦方向に並べる。
- カード内はPCと同じく上位3件を基本とするが、1件あたりの表示は短く保つ。
- 下段3ブロックも縦積みにする。
- 横スワイプ前提にはせず、縦スクロールで完結できることを優先する。
- 詳細は全幅に近いModal / Sheetで表示する。
- 重要情報の順序はPCと同じ意味構造を維持する。

推奨Mobile順序:
1. 日付 / 今日のモード
2. 自分が動く
3. 手放す
4. 褒める
5. 詰まりを取る
6. 当日のスケジュール
7. 今月の進捗 + AIコメント
8. チーム状態
9. Decision Pack状態 / データ鮮度など補助情報

## 6. Home UX原則

- 空でも不安を煽らない。
- 異常があっても過度に警告しない。
- 情報量は濃くても、心理負荷は軽くする。
- マネージャーが「責められている」と感じるUIにしない。
- 重要なのは危機感の演出ではなく、判断と次の一手の明確化。
- COMESは管理圧ではなく、判断支援のためのManagement OSである。
