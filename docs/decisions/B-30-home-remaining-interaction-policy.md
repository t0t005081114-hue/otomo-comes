# B-30 HOME残論点：表示・操作・初回導線・更新方針

Status: Accepted v0.2

## 1. 今日のモード

HOME上部には独立カードを置かず、1行表示とする。

表示内容:
- 今日のモード
- AIコメント

目的:
- その日のマネージャーとしての重心を一目で把握する
- 下段の「今月の進捗＋AIコメント」と競合しない情報量に抑える

## 2. Decision Pack状態

HOME上ではステータス表示のみとする。

過剰な警告・CTA化はしない。

Decision PackをHOMEから `確認済み` に変更する操作は持たない。確認・確定はDecision Pack画面で行う。

## 3. クイック操作

HOMEから許可する主操作は以下の3つとする。

- 完了
- タスクを見る
- 保留

詳細編集や複雑な操作はHOMEに持ち込まない。

## 4. 初回利用時の設定導線

初回セットアップは以下の順で案内する。

1. KPI設定
2. メンバー設定
3. 予定連携

この順序は、COMESが判断材料を作るための最小前提を段階的に揃えることを目的とする。

## 5. 日次AI分析結果の扱い

HOMEでは、**翌朝時点でCOMESへ取込済みの最新AI分析結果**を、その日の判断基準として固定利用する。

基本フロー:

```text
前日締め
→ Decision Pack
→ 外部AIで分析
→ COMESへ結果取込
→ 翌朝時点で取込済みの最新結果をHOMEの基準として固定
```

個人MVPは外部AIへのコピー / JSON貼り戻しを人間が行うため、毎朝必ず新しいAI結果が存在することは前提にしない。

原則:
- 翌朝時点で新しい結果が取込済みなら、その結果を当日の基準にする。
- 日中に新しいAI結果を取り込んでも、その日の `今日のモード` と基準AIコメントを自動で頻繁に切り替えない。
- 新しい結果の存在自体は確認可能にしてよいが、当日の基準変更は翌朝単位とする。
- AI結果が一度も存在しない場合は、未生成 / 未取込として静かに表示し、存在しない判断を補完しない。

これにより、朝時点のマネジメント判断を安定して提示する。

## 6. 設計原則

HOMEは高密度なコクピットである一方、判断負荷を増やさない。

- AIの判断は簡潔に表示する
- 状態表示は静かに見せる
- クイック操作は最小限にする
- 初回セットアップは順序を明確にする
- 日次AI判断は翌朝単位で安定させる
